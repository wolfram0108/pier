# Карта кода

Одна страница о том, где что лежит и по какому правилу. Требований здесь нет:
их источник один — `TZ.md` миссии `doc/missions/singbox-router-panel/` в рабочем
каталоге разработчика. Здесь только устройство кода.

## Раскладка

```
cmd/pier/           запуск: собирает зависимости и отдаёт управление, логики нет
internal/
  clock/            время: единственный «сейчас» в программе
  fail/             ошибки: каталог кодов и русских текстов
  event/            события: шина, один поток на клиента
  model/            сущности и отпечаток, без поведения
  settings/         каталог настроек: умолчания, пределы, проверка
  parse/            разбор ссылок и подписок
  flash/            хранилище: единственная точка записи на флеш
  confgen/          генератор конфигурации ядра: чистая функция
  core/             привязка к ядру: процесс, управляющий интерфейс, применение
  sysbind/          привязка к ОС: сетевые интерфейсы, firewall, служба
  probe/            движок проверки: очереди, порции, ранжирование
  state/            состояние: истина о нодах, группах, составах
  api/              HTTP: маршруты, коды ответов, поток событий
  webui/            интерфейс: исходные файлы и склейка
packaging/          пакет .ipk, служба procd, установщик
```

Слои повторяют § 4.2 ТЗ один в один — так, чтобы название пакета отвечало на
вопрос «какой это слой», а не «что там внутри».

## Правило зависимостей

Импорт идёт **строго вниз** по уровням. Уровень выше знает про нижние, обратное
запрещено.

| Уровень | Пакеты | Кому разрешено импортировать |
|---|---|---|
| 0 | `clock`, `fail` | никого |
| 1 | `model` | уровень 0 |
| 2 | `event`, `settings`, `parse` | уровни 0—1 |
| 3 | `flash`, `confgen` | уровни 0—2 |
| 4 | `core`, `sysbind`, `probe` | уровни 0—3 |
| 5 | `state` | уровни 0—4 |
| 6 | `api` | уровни 0—5 |
| 7 | `webui` | ничего (только свои файлы) |
| — | `cmd/pier` | всё |

Два запрета сверх уровней, оба из ТЗ:

| Запрет | Откуда |
|---|---|
| `probe` не импортирует `core` и `state` | § 4.2: движок проверки не знает ни о панели, ни о ядре напрямую. Всё, что ему нужно, он объявляет своими интерфейсами, а подставляет их `cmd/pier` |
| никто не импортирует `api` | API — дверь наружу, а не библиотека для своих |

Правило не на словах: `internal/arch_test.go` читает импорты всех пакетов и
падает, если кто-то посмотрел вверх или в запрещённую сторону.

## Куда что добавлять

Расширение — правка **одного** места. Если приходится трогать два и больше,
это сигнал, что каркас неверен, а не что задача такая.

| Что добавляем | Куда |
|---|---|
| протокол ноды | `parse/proto_<имя>.go` + строка в его каталоге |
| формат подписки | `parse/format_<имя>.go` + строка в его каталоге |
| настройку | `settings/catalog.go` — одна запись со значением, пределами и текстом |
| код ошибки | `fail/catalog.go` — код, русский текст, HTTP-ответ |
| событие потока | `event/kinds.go` — имя и поля |
| метод API | `api/routes.go` — строка таблицы, рядом обработчик |
| сущность состояния | `model/` — описание, `state/` — работа с ней, `flash/` — запись |

## Сквозные правила

| Правило | Причина в ТЗ | Как обеспечено |
|---|---|---|
| время только монотонное | Н-5.6: на роутере нет часов, дата после перезагрузки врёт | `clock` — единственный источник; `time.Now()` вне него запрещён тестом |
| единственная точка записи на флеш | § 4.3, Н-3.1 — Н-3.3 | пишет только `flash`, он же считает записи |
| состояние меняется последовательно | Ф-8.7 | у `state` одна очередь изменений |
| у изменяемой сущности есть версия | Ф-8.8 | поле `Version` в `model`, проверка в `api` |
| ошибка = устойчивый код + готовый русский текст | Ф-8.2, И-7, Т-1 | `fail`: текст живёт рядом с кодом, а не в обработчике |
| ядру видна не более одной порции от процесса | И-2 | `probe` держит порции, `core` их только показывает |
